Accessibility

Last reviewed {{EFFECTIVE_DATE}}

Sticker Showdown is a small, fast game. This page explains what has been done to make it usable with keyboards, screen readers, and different screen sizes, and where the limits are. It is an honest description of the current build rather than a claim of full conformance.

1. Design decisions

  • Semantic HTML landmarks, headings in order, and a skip link to the main content.
  • Every form field has a visible label. Errors are announced through alert regions.
  • Keyboard focus is always visible, with a high contrast focus ring.
  • Controls are rectangular with large touch targets; the send control is at least 5.5rem tall on phones.
  • Text and background colours were chosen for readable contrast on the parchment background.
  • Motion is limited. Reduced motion preferences are respected by the stylesheet.
  • The interface does not play audio, vibrate, or autoplay media.
  • There are no colour-only status indicators. Every status also has text.

2. Keyboard operation

  • Tab and Shift+Tab move between links, fields, and buttons.
  • Enter or Space activates buttons. The name and room code fields submit with Enter.
  • Keys 1 to 6 select a sticker from the tray during a match.
  • Holding the send button with a pointer repeats sends at the allowed rate. Pressing Enter or Space sends one sticker per press.
  • Leaving a live match asks for confirmation in a native dialog that traps focus.

3. Screen readers and score updates

Rapidly changing scores are not announced on every point, because that would make the game unusable with speech. The score itself is available as text on the screen and updates in the accessible tree. A polite live region announces the score at most once every six seconds during a round, and the final result is announced once when the round ends.

The connection status and room notices use a polite live region. The sticker feed is deliberately hidden from assistive technology, because it changes many times per second.

4. Known limitations

  • The core game is timing based and simultaneous. Screen reader users may need a longer round or a second person to play competitively.
  • Sticker artwork is user supplied. Alt text falls back to a general description unless the deployment provides a manifest with descriptive text.
  • Some mobile browsers resize the viewport when scrollbars appear. The layout uses modern viewport units where supported.
  • The game needs JavaScript. Without it, the legal pages remain readable but a match cannot run.
  • Automated testing covers markup and keyboard structure, but no formal audit by a third party has been completed.

5. Feedback

If something blocks you from playing, contact {{CONTACT}} and describe the device, browser, and assistive technology you used. Reports are used to fix issues in later versions.
